# 사후 보정을 끈 원본 추정기 진단과 수정

이번 작업에서는 사후 보정을 적용하지 않았다. 원본 `KnowledgeEstimator`를 보존하고,
시간 처리만 고친 `RawKnowledgeEstimatorV2`를 추가했다. **일반 2D 예측 성능이 개선됐다는 결과는 아니다.**

## 1. 원인 분류

| 분류 | 확인한 내용 | 조치와 이유 |
|---|---|---|
| 구현 문제 | 중복 ACK/send/RESULT/검증 결과, ACK 이후 timeout 처리에서 조기 반환이 시간 갱신보다 먼저 실행됐다. `estimate()`를 직접 호출하면 C가 만료되지 않을 수 있었다. | 다섯 경로에서 처리 시각을 먼저 반영한다. 중복 근거는 계속 추가하지 않으며, 저장 시각·관측 시각도 갱신하지 않는다. |
| 모델 가정 | 통과 획득률은 경로·장소·계획 속도별 주변 빈도다. 통신 실패를 본 뒤 통과 획득 확률을 다시 계산하지 않는다. 현재 시뮬레이터는 같은 벽을 시각 가림과 LOS 통신에 사용하므로 두 사건이 관련될 수 있다. | 관련성의 증거는 있으나 일반적인 결합 모델로 바꾸지는 않았다. 통과-전송 연결, 간격, 재시도·이동, ACK 손실을 구분한 수집이 필요하다. 지금 확률을 일괄 하향하면 조건에 따라 틀릴 수 있다. |
| 모델 가정 | 기본 근거 결합은 `max`이며 코드도 `union_lower_bound`라고 명명한다. 임의 의존성을 허용하는 보수적 하한이지, 실제 합집합 확률을 정확히 구한 값은 아니다. | 독립성이 입증되지 않아 곱셈/독립 합집합으로 바꾸지 않았다. Brier 평가 수치는 계산하되 이를 완전히 보정된 확률이라고 부르지 않는다. |
| 관측 부족 | B 메모리가 초기화돼도 STATUS가 없으면 A의 입력은 동일하다. | 숨은 정답을 입력하거나 임의의 기억 감쇠율을 추가하지 않았다. epoch/boot STATUS 전달 또는 별도 유지율 측정이 필요하다. |
| 관측 부족 | 미측정 route/channel/content 조건은 필요한 확률이 없다. ACK는 저장 R을 확인해도 내용 유효성까지 측정하지 않는다. | 미측정은 `None`으로 유지한다. 전송 대기·통과 이력 없는 전송에 보정표가 없다는 문제와 raw 계산 가능 여부를 구분한다. |

구현 근거: `probabilistic/estimator.py`의 각 조기 반환과 `_tick`, `estimate`의 TTL 판정.
모델 근거: 같은 파일의 `_apply_pass`, `observe_ack_timeout`, `estimate` 및
`simulation/world.py`, `simulation/run.py`의 시야·채널 생성 로직.
이번 수정은 로컬 코드와 로그에서 확인한 문제를 고친 것이며 특정 논문의 재현이라고 주장하지 않는다.

기존 source 72개에서 통신 결과별 획득 횟수는 다음과 같다. 이 표는 **진단용**이며 새 확률로 넣지 않았다.
같은 설계 격자 안의 조건부 횟수이며 실측 센서 성능이나 독립 표본 통계가 아니다.

|---|---:|---:|---:|---:|

실제 전달 여부는 현재 평가 정답이므로 A에 입력할 수 없다. no-ACK를 통한 업데이트를 설계하려면
전달 실패와 ACK 손실을 구분하는 관측 모델을 독립 source 데이터에서 정해야 한다.

## 2. ACK에 관해 바로잡을 점

`after_channel`에는 ACK 수신과 ACK 없이 timeout한 사례가 **둘 다** 포함된다.
따라서 그 평균을 ‘정상 ACK 직후의 오류’라고 부르면 정확하지 않다.
이번 최종 평가에서는 정상 채널 24개 중 실제 ACK 수신이 12개다.
그 12개의 ACK 시점에서 raw N/C/I Brier는 모두 0이다.

이는 이 시뮬레이터가 전송 내용의 유효성을 이상적으로 1로 두기 때문이다.
일반적으로 ACK는 저장 R만 보장한다. I/C의 유효성은 별도로 측정한 `r_crop`/`r_current`,
버전·좌표계·TTL 등을 따라야 한다. 테스트에서는 품질을 0.5로 준 경우 ACK 후에도 K 추정이
0.5로 유지되고, 품질 미측정이면 R=1이어도 K는 `None`임을 확인했다.
정상 ACK 값을 보정표 때문에 일괄 낮출 근거는 확인되지 않았다.

## 3. 원본과 수정본의 차이

| 항목 | 원본 | 수정본 |
|---|---|---|
| 이벤트 중복 처리 | 근거를 중복하지 않지만 일부 경로에서 시간도 멈춤 | 근거 중복을 막으면서 시간은 진행 |
| 중복 이벤트 후 직접 `estimate(C)` | 지난 시각으로 TTL을 계산할 수 있음 | 최신 이벤트 시각으로 TTL 계산 |
| 만료 후 저장 여부 R | 저장 근거 유지 | 동일하게 유지 |
| ACK, 통과 확률, 내용 품질, 근거 결합 | 기존 측정 파라미터·규칙 | 동일 |
| 미측정 확률 | `None` | 동일 |
| 사후 보정 | 비교에서는 끔 | 끔 |

원본 파일은 수정하지 않아 기존 모델 fingerprint와 재현성을 유지했다.
수정본은 별도 fingerprint를 가진다. 기존 보정 모델을 수정본에 재사용해서는 안 된다.
기존 호출부를 자동 전환하지 않았으며 수정본 사용은 명시적으로 선택한다.

```python
from knowledge_estimation.probabilistic import RawKnowledgeEstimatorV2
estimator = RawKnowledgeEstimatorV2(parameters=parameters)
# 기존 EstimatorAdapter에 이 인스턴스를 전달하면 ROS와 무관한 동일 계약을 사용한다.
```

시각 역행은 수정본에서 중복 이벤트에도 거부한다. 유효하지 않은 호출도 처리 시각은
진행할 수 있으므로 호출자는 직렬·단조 시각을 사용해야 한다.

## 4. 별도 데이터에서 수정 전후 비교

결과: `data/raw_revision_v1/summary.json`, `test/metrics.csv`, `test/conditions.csv`.
보정표를 계산 함수에 전달하지 않고 원본 raw와 수정본 raw만 비교했다.
기존 보정 산출물은 source 파라미터 출처·기존 그룹 중복 검사에만 참조했다.
원본 감사 실행기의 내부 `cal` 열은 이 모드에서 비어 있으며 비교 대상이 아니다.

코드·source 파라미터와 두 격자를 먼저 고정한 후 validation, test 순서로 실행했다.
validation을 보고 모델이나 수치를 다시 선택하지 않았다.
validation: offset 0.32/1.32m, heading 42/132도.
test: offset 0.38/1.38m, heading 48/138도.
각각 속도 0.5/1/2m/s × 벽 유무 × 12개 개입으로 288에피소드다.
한 분할당 실제 기하 설계는 24개이며, 개입 간 같은 기하를 재사용한다.
기존 source 빈도는 그대로 사용했고 새 학습이나 보정 학습은 하지 않았다.
전후에 관측·정답·물리 trace가 바이트 단위로 같음을 검사했다.
새로운 실험 조건으로 만든 합성 데이터이며 실측 D455 결과가 아니다.

최종 test 결과, Brier는 낮을수록 좋다. 표본 수는 각 조건·항목별 예측 수다.

조건·시점·항목 198그룹 중 비교 가능한 193그룹은 전부 동일했다.
**개선 0, 악화 0, 동일 193, 모두 미지원 5**다. 부분 미지원 그룹도 표본/paired/missing을 CSV에 표시했다.

별도 중복 이벤트/만료 계약 검사는 분할마다 5경로 × 4시점 = 20개다.

이는 의도적으로 재현한 API 버그의 해결 결과이지 일반 획득 성능 개선이나 물리 에피소드 20개가 아니다.

## 5. 아직 보정을 다시 켜지 않는 이유

남은 큰 오류는 숨은 초기화처럼 현재 입력으로 식별할 수 없는 상태, 획득률의 조건별 분포 차이,
결합 모델의 보수적 하한과 관련된다. 보정으로 상태 관측을 대신하면 ACK가 확인한 저장까지
희석하거나 숨은 reset을 감지한 것처럼 오해할 수 있다.

다음 원본 모델 변경에는 통과-전송 연결·시간 간격·채널 조건이 명시된 별도 source 수집과
결합 관측 모델의 검증이 필요하다. 그 전에는 현재 확률을 유지한다.
원본 모델과 관측 계약을 확정한 뒤, 새 validation에서 확률과 실제 보유율이 계속 어긋나는
지원 조건에 한해서 보정 필요성을 검토한다. 이번 test 결과를 다시 튜닝에 사용하면 후속
최종 평가는 새 데이터로 해야 한다.

재현:

```powershell
python -m knowledge_estimation.simulation.compare_raw --output knowledge_estimation/data/raw_revision_new
python -m unittest discover -s knowledge_estimation/tests -p test_*.py
```
