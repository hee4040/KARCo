# 이번 정리의 검증 기록

실제 로봇 성능 결과가 아니라 소프트웨어 계약 검증 기록이다.

- `python -m unittest discover -s knowledge_estimation/tests -q`: 46개 통과.
- 실제 로컬 규칙 ref의 원본 패키지를 임시 폴더로 읽어 명명된 N/I/C 입력,
  SEND/NO_COMM/REOBSERVE, 정책 설정 출처와 fingerprint 차단을 검사했다.
- 파라미터 없음/fixture/조건 미측정/미주석 정답/보정 범위 밖 상태를 임의 수치로
  대체하지 않는 경로를 검사했다.
- CSV → source 적합 → A-only 재생 → 고정 score 보정 → 평가의 fixture smoke가 통과했다.
  자동 검사는 임시 폴더를 사용한다. 이전 ignored `data/contract_check/` 출력은 정리했다.
- fixture를 기본 모드로 보정하려는 CLI는 오류로 종료했고 출력 파일을 만들지 않았다.
- 미정인 root 평가 계획으로 실행하려는 CLI도 오류로 종료했고 보고서를 만들지 않았다.
- `compileall`, Git whitespace 검사가 통과했다.

검사에는 미측정 무ACK 이벤트의 원본 보관, 외부 정답의 지연 주석, 주석이 원본 DB의
버전·시각·멤버십을 바꾸지 못하는 것, TTL/잘못된 crop/frame의 R/K 분리,
동일 crop 재전송, 반복 통과·같은 가림의 중복 방지, 전후 layout 일치,
실측 source 빈도와 조건부 ACK 분모, CDF 관측 horizon, epoch/version/폐기 증거,
신경망 없는 고정 보정, 데이터 누수·체크섬, 작은 표본 구간을 포함한다.

현재 `params.yaml`은 미측정이다. 실제 카메라 로그, B 로봇 DB/저장 시험,
측정에 근거한 파라미터, 하드웨어 통합, 정책별 전체 에피소드 성공률/Pareto 비교는
아직 수행하지 않았다. 이전 2D 합성 성능 수치를 현 구현의 성능으로 재사용하지 않는다.

추가한 D455 기준 2D 검사는 시야 방향/최소·최대 optical Z/가림, 관측 시간 저장 gate,
시간 간격 축소 시 저장 시각 차이, 원시 통과 이력과 성공 수의 일치,
source와 test 에피소드 분리, 비공개 메모리 초기화의 A 추정 불변성,
simulation 기본 거절, 결정적 조건 순회에서 신뢰구간 미출력을 확인한다.
네이티브 Tk 재생 창은 제공하지만 자동 GUI 시각 검사는 수행하지 않았다.

test 48개 에피소드의 288시점에서 다음 Brier를 얻었다(낮을수록 좋음).

| 항목 | raw | 보정 후 |
|---|---:|---:|
| N | 0.21398 | 0.18155 |
| C | 0.04167 | 0.03125 |
| I | 0.23134 | 0.19742 |

카메라 방향·벽·재시작을 정해진 조합으로 순회한 결과이며, 실제 D455 인식 정확도나
실제 로봇의 확률 보정 성능을 의미하지 않는다. 실험 조건과 한계는 SIMULATION_PROTOCOL.md에 기록했다.

## 추가 조건 분석

`data/d455_conditions_v1/`: 별도 360 에피소드(source 72/보정 144/test 144).
source에서 N 55/72, I 48/72를 획득했다. test 통과 획득률은 reset 유무 중복을 제거한다.
속도별 test I 획득률은 0.5m/s:20/24, 1m/s:18/24, 2m/s:16/24다.
계획 속도는 A가 아는 condition_id에 넣고, 실제 방향/가림/메모리 초기화는 평가에서만 읽는다.

전체 test Brier는 N 0.21976→0.18618, C 0.04167→0.03125, I 0.22483→0.19389다.
그러나 통과 직후에는 보정이 악화되는 조건이 있다. 예: 0.5m/s의 I는 0.14063→0.17517이다.
현재 항목별 보정표가 전체 단계를 함께 적합하므로 전체 평균 개선을 모든 조건 개선으로 해석하면 안 된다.
이미 확인한 test 결과를 보고 같은 test에 맞춰 보정표를 다시 적합하지 않았다.
향후 단계/출처별 보정 설계를 바꾸면 별도 validation과 새 최종 test가 필요하다.
속도별 source context·CDF 관측 범위 분리와 reset 중복 제거도 자동 검사에 포함했다.
연속 관측 시간은 누적 덧셈 대신 연속 가시 프레임 구간 수×dt로 계산해, 30Hz의 0.3/0.6초
gate가 부동소수점 누적으로 한 프레임 늦어지는 것을 막았다. 해당 경계 시각도 자동 검사한다.

## 보정 수정과 별도 검증

`data/calibration_repair_v1/`: 새 source 72/calibration 144/validation 144/final test 144,
총 504 에피소드다. 각 분할의 거리·방향 조건과 episode/session/instance/route group을 분리했다.
기존 360개는 원인 분석에만 사용했다.
validation의 통과 직후 N/I 평균 Brier로 증거 종류별 보정을 선택하고 selection.json을 고정한 뒤
처음으로 final test를 생성했다. test를 보고 모델을 재선택/재적합하지 않았다.

| 새 최종 test | 기존 pooled | 증거 종류별 보정 | raw |
|---|---:|---:|---:|
| 통과 직후 N Brier | 0.18263 | 0.14728 | 0.14873 |
| 통과 직후 I Brier | 0.21391 | 0.17593 | 0.18519 |
| 전체 N Brier | 0.18309 | 0.16676 | 0.21436 |
| 전체 C Brier | 0.03125 | 0.03125 | 0.04167 |
| 전체 I Brier | 0.19081 | 0.17464 | 0.21943 |

통과 직후 평균 악화는 개선됐지만 모든 조건을 개선한 것은 아니다.
최근접 거리 0.15m의 N/I, 벽이 있는 I 등에서는 기존 pooled보다 악화된 집계가 남는다.
증거 종류는 A 이력에서만 계산하며 phase/reset/가림/DB 정답은 모델 입력이 아니다.
처음 보는 증거 종류나 보정 지지 범위 밖 점수는 pooled로 대체하지 않고 거절한다.
자동 검사는 런타임/평가 경로의 같은 보정, 미관측 context 거절, TTL invalid=0,
최종 test 라벨 변경 시 적합 보정표 불변, validation 선택 후 test 생성과 분할 불중복을 확인한다.

## 고정 추정기 12상황 검증

`data/estimator_verification_v1/`: 새 기하 조건 72개 × 개입 12개 = 864 에피소드.
선택 모델·source 파라미터·raw 구현 fingerprint를 고정하고 학습 없이 실행했다.
4,104 체크포인트, 12,312 항목 예측, 시나리오 논리 검사 1,368개(실패 0개)다.
같은 기하를 공유한 개입은 독립 실측 반복으로 간주하지 않는다.

보정 지원은 항목 기준 9,972/12,312, N/C/I 모두 지원하는 체크포인트는 3,276/4,104다.
미지원 2,340건은 점수 0으로 바꾸지 않았다. 표본을 함께 지원하는 경우의 Brier도 별도 기록했다.
통과 직후 N/I는 개선됐지만 정상 채널 처리 직후 N은 raw 0.08189→cal 0.19702,
I는 raw 0.10822→cal 0.20473으로 악화됐다. 재전송 ACK 직후에도 하향 보정 오류가 있다.
미보고 reset 이후에는 보정이 평균 오류를 줄여도 실제 reset을 알아내지 못한다.
전송 대기와 통과 이력 없는 전송은 보정 지원 부족, 미측정 route/channel은 명시적 거절이 발생한다.

논리 통과와 추정 정확도/지원 범위 충족은 다르므로 전체 사용 준비 완료로 판정하지 않는다.
진단만 수행했고 새 검증 라벨로 재학습하지 않았다. ESTIMATOR_VERIFICATION.md를 따른다.

## 원래 값 유지와 선택적 보정 비교

`data/selective_calibration_v2/`: 새로운 validation 288 + final test 288 에피소드.
기하 조건 24개 × 개입 12개이며 같은 기하를 공유한 개입은 독립 실측 표본이 아니다.
validation은 수집 시작부터 validation split으로 기록하고, 선택 모델/게이트 hash를 고정한 뒤
final test를 처음 생성했다. source 확률과 기존 보정표 자체는 재적합하지 않았다.

정확한 ACK 처리 시각을 새로 기록했다. 정상 ACK의 N/I는 각 n=12에서 기존 보정 Brier
0.11111→수정 후 0, C는 0.06250→0이었다. 이 값은 이상적 내용 유효성=1인 시뮬레이션에서
원래 값을 유지한 결과다. ACK만으로 K=1을 강제한 것이 아니다.
채널 처리 후(n=24)는 N 0.20396→0.09462, I 0.21245→0.10475였다.
반면 미보고 reset 후(n=24)는 N 0.31507→0.59285, C 0.28125→0.5,
I 0.28652→0.56430으로 악화됐다. 해당 평가 후 선택 게이트를 바꾸지 않았다.

항목 4,392개 중 raw/수정 후 제공 4,236개, 기존 보정 제공 3,588개다.
보정 지원이 늘어난 것이 아니라 기존 보정 미지원에서 원래 값이 유지된 경우를 포함한다.
미측정 raw 156개는 여전히 None이며 임의로 채우지 않았다.
케이스/시점/항목 집계는 개선 51, 악화 3, 동일 111, 짝지은 비교 불가 33개이며
거리·방향·속도·벽별 세부 집계의 악화도 CSV에 보존했다.
자동 검사에는 R=1/K=0.5 구분, 내용 계수 미측정 시 K=None 유지, fresh ACK 보호,
보정 상향 허용, 범위 밖 raw 유지, 정책 선택 후 final 생성, native validation 분할 검사가 포함된다.
