# 선택적 보정: 원인별 분석과 별도 평가

ACK 직후 원래 추정값을 보존하고, 다른 조건에서도 별도 검증에서 개선이 확인될 때만 보정하도록 수정했다.
기존 보정표와 획득/수신 확률은 고정했다. 수정 후 모든 조건이 좋아진 것은 아니다.
미보고 메모리 초기화에서 악화됐고, 실제 D455 영상·깊이 오류나 실측 reset 분포는 검증하지 않았다.

## 1. ACK의 보장과 내용 유효성

코드 `KnowledgeEstimator.observe_ack`는 보고된 epoch/항목/버전의 저장 사실에 대해 p_stored=1을 넣는다.
내용 유효성은 별도 p_usable_given_stored를 사용한다. ACK 하나만 고려하면 K는 R×내용 유효성이다.
기존 통과 등 다른 근거도 있으면 원래 추정기는 그 근거들을 결합한다.

| 값 | 의미 | ACK로 확정되는가 |
|---|---|---|
| R | 해당 보고 조건에서 저장됐다는 사실 | 올바른 epoch/항목/버전의 ACK가 확인. 이후 영구 보존을 보장하지 않음 |
| N의 유효성 | A가 승인한 정상 배치와 버전/frame 등 일치 | 등록·프로토콜 조건도 필요 |
| I의 유효성 | 올바른 물체의 사용할 수 있는 외형 내용 | r_crop 등 별도 근거 필요 |
| C의 유효성 | 현재 pose 내용·버전/frame·관측 시각의 TTL 유효 | r_current 및 만료 검사 필요 |

따라서 ACK로 I/C의 K를 무조건 1로 바꾸면 안 된다. 기존 코드도 R 자체를 낮춘 것은 아니다.
문제는 R/내용 유효성을 결합한 최종 K 점수를 사후 표가 다시 낮춘 것이다.
현재 2D는 정확한 내용을 생성하므로 r_crop=r_current=1이고, fresh ACK의 raw=1이 맞는다.
실제 로봇의 내용 유효성이 1이라는 증거는 아니다.
자동 검사에서 실제와 무관한 명시적 fixture 계수 0.5일 때 ACK 뒤 R=1/K=0.5가 유지됨을 확인했다.
내용 계수가 미측정인 경우 ACK 뒤에도 K=None을 유지하며 fallback으로 1을 채우지 않는다.

## 2. 원인별 진단

### 정상 ACK 직후 오류

기존 source-only 보정은 같은 증거 종류의 새 ACK와 오래된 ACK를 구분하지 않았다.
N/I의 `[ack,pass_by]` 표는 raw 1의 기록 216개 중 K=1이 144개라 2/3으로 만들었고,
C의 `[ack]` 표는 144개 중 108개라 0.75로 만들었다. 이 기록에는 미보고 reset 이후도 섞였다.
직후에도 이를 적용하면 올바른 N/I의 제곱 오류는 (1−2/3)²=0.11111이 된다.

이전 after_channel 체크포인트는 ACK 수신과 timeout을 합친 시점이었다. 이번에는 정확한
ACK 처리 시각의 at_ACK를 별도로 추가해 수신 직후를 직접 비교했다.
현재 이상적 내용 모델에서 fresh ACK에 추가 보정은 필요하지 않았다. 현실에서는 내용 유효성,
나중의 retention/epoch 불확실성, 실제 측정 오류가 검증되면 그 항목을 별도로 수정해야 한다.
가상의 reset 비율을 섞어 fresh ACK까지 일괄 낮추는 것은 근거가 부족하다.

### 전송 대기 미지원

기존 보정 데이터의 send 체크포인트는 전송 명령 전이었다. 실제 전송 직후 생기는 `send`
또는 `[pass_by,send]` 근거는 학습 표에 없었다. raw는 기존 수신 CDF/통과 이력으로 계산되지만
사후 보정 함수가 미관측 source 조합을 거절해 최종 값이 나오지 않았다.

### 통과 없는 전송 미지원

보정 학습 에피소드가 항상 통과를 먼저 수행했다. 따라서 N/I에 `[ack,pass_by]`,
`[ack_timeout,pass_by]`는 있지만 ACK/timeout 단독 표는 없었다. 원래 계산이 틀려서가 아니라
보정 훈련 범위와 엄격한 거절 정책의 문제였다.

### 미측정 입력과 가정 위반

미측정 route/channel은 원래 확률도 모르는 경우이므로 숫자를 만들어서는 안 된다.
ACK를 강제로 억제하는 실험은 고정 p_ack=1 모델을 의도적으로 어긴 스트레스 조건이다.
그 결과로 채널 성공률을 새로 꾸며 넣지 않았다. 누락 원인과 raw 모델 가정의 오류는 별도 문제다.

## 3. 수정 규칙과 근거

`application_policy=validation_gated_raw_fallback_v1`을 추가했다.

1. hard-invalid/만료는 기존 유효성 규칙대로 0. 원래 미측정인 raw는 None.
2. ACK가 현재 결정 시각에 처리됐다면 원래 R/내용 유효성/버전/만료 계산을 그대로 유지한다.
3. 그 외에는 A가 아는 각 증거 종류와 현재 시각에 생긴 증거인지/이전 증거인지만 구분한다.
   임의의 '몇 초면 오래됨' 기준이나 숨은 reset/벽/단계 이름은 쓰지 않는다.
4. 해당 조건의 학습 기록, 별도 검증 기록, 보정 지원 범위가 없으면 raw를 유지한다.
5. 검증에서 최소 두 가지 기하 조건을 비교할 수 있고, 기존 보정이 raw보다 엄격히 낮은
   Brier를 보인 조건만 적용한다. 동률도 raw다. 2개는 단일 조건만으로 교차조건 검증을 하지 않기 위한
   다양성 하한이며 통계적 충분성/유의성의 증거는 아니다.
6. 적용 승인된 조건도 실행 중 점수가 지원 범위를 벗어나면 raw를 유지한다.

검증 Brier는 동일 기하를 공유한 개입/체크포인트를 기하별 평균으로 묶어 비교한다.
어떤 항목도 확률을 반드시 낮추는 cap을 넣지 않았다. 표가 올려 주는 경우도 검증 승인 시 허용한다.
보정 상향과 raw=0/0.2/0.8/1 유지, 보정 범위 밖 유지도 자동 검사했다.
실제 최종 평가에서도 통과 직후 N의 0.79167을 검증 승인된 표로 0.81250으로 올린 사례가 있다.
전체 체크포인트 항목 중 raw 대비 상승 456건/하락 48건이었으며, 이는 독립 시행 수가 아니라 기록 수다.

예를 들어 N/I 통과 직후는 기존 학습 144개 기록, 새 검증 264개 기록(고유 기하 24개)에서
개선이 확인돼 적용했다. 전송 대기 source 조합은 학습 0개여서 적용하지 않았다.
ACK 이후 조건도 검증에서 raw보다 좋아지지 않아 적용하지 않았다.
학습/검증 기록 수는 독립 물리 표본 수가 아니다. 실제 환경에서 충분한 데이터라는 주장도 아니다.

런타임 project/evaluate는 같은 calibration_result를 호출한다. b_cal 필드는 최종 선택 점수이며,
raw를 유지한 경우도 포함한다. project.application_reasons와 비교 CSV에 적용/유지 이유를 기록한다.
기존 calibrated 플래그는 모델이 구성됐다는 호환 정보이므로 모든 항목에 표를 적용했다는 뜻으로 쓰지 않는다.

## 4. 별도 평가 설계

- 기존 source 확률/보정표를 그대로 두고 새 validation 288 에피소드에서 적용 여부만 선택했다.
- 검증의 offset은 0.12/1.12m, heading 28/118°, 속도 0.5/1/2m/s, 벽 유무다.
- 게이트와 모델 ID/hash를 저장한 뒤 새 final test 288 에피소드를 생성했다.
- 최종 offset은 0.24/1.24m, heading 36/126°다. 검증과 다른 실제 기하 및 그룹 ID를 사용했다.
- 각 분할은 기하 24개 × 개입 12개다. 동일 기하를 공유한 개입을 독립 표본으로 세지 않는다.
- validation은 수집 시작부터 validation split으로 기록했고 원시 로그를 나중에 바꾸지 않았다.
- 최종 평가 뒤 결과를 보고 게이트/보정표를 다시 선택하거나 적합하지 않았다.
- 같은 A 이력/같은 B 정답에서 raw·기존 보정·수정 후를 비교했다. 새로운 통신 정책 실험은 아니다.

## 5. 최종 평가 결과 — 개선과 악화 모두

Brier는 낮을수록 좋다. 표의 n은 각 항목의 해당 시점 표본 수다.

| 상황 | 항목 | n | raw | 기존 보정 | 수정 후 |
|---|---|---:|---:|---:|---:|
| 통과 직후 | N | 24 | 0.12326 | 0.12124 | 0.12124 |
| 통과 직후 | I | 24 | 0.16782 | 0.14931 | 0.14931 |
| 실제 ACK 수신 시각 | N | 12 | 0 | 0.11111 | 0 |
| 실제 ACK 수신 시각 | C | 12 | 0 | 0.06250 | 0 |
| 실제 ACK 수신 시각 | I | 12 | 0 | 0.11111 | 0 |
| 채널 처리 후(ACK/timeout 포함) | N | 24 | 0.09462 | 0.20396 | 0.09462 |
| 채널 처리 후(ACK/timeout 포함) | I | 24 | 0.10475 | 0.21245 | 0.10475 |
| **미보고 reset 후** | **N** | **24** | **0.79253** | **0.31507** | **0.59285** |
| **미보고 reset 후** | **C** | **24** | **0.50000** | **0.28125** | **0.50000** |
| **미보고 reset 후** | **I** | **24** | **0.72975** | **0.28652** | **0.56430** |

새 ACK의 0점은 현재 무오류 내용 생성/등록 조건 안에서의 결과다. 실제 센서 오류가 0이라는 뜻은 아니다.
ACK를 보호한 대신 미보고 reset 후 과확신이 커진 것이 명확한 부작용이다.
특히 벽 없는 reset 조건(n=12)은 N/I 기존 0.44444→수정 1.0, C 0.56250→1.0으로 악화됐다.
A가 받는 이력이 같으면 실제 reset 여부를 구분할 수 없다. 향후 측정된 retention 모델이나
추가 STATUS/캐시 증거가 필요하며, 이번 평가 결과를 보고 임의 decay를 넣지 않았다.

조건별 집계는 `final_by_condition.csv`에 속도·거리·방향·벽별 n과 동일 표본의 전후 Brier를
모두 기록했다. 악화 조건도 필터링하지 않았다. 서로 겹치는 조건별 집계를 독립 표본으로 합산하지 않는다.
케이스/시점/항목 집계는 개선 51개, 악화 3개, 동일 111개, 전후 비교 불가 33개다.
이 숫자는 정확도나 개선 확률이 아니라 체크포인트 집계 분류다.

## 6. 미지원과 raw 유지의 결과

| 상황/항목 | n | 기존 보정 지원 | 수정 후 지원 | 수정 후 Brier |
|---|---:|---:|---:|---:|
| 정상 전송 대기 N | 24 | 0 | 24 | 0.12326 |
| 정상 전송 대기 C | 24 | 0 | 24 | 0 |
| 정상 전송 대기 I | 24 | 0 | 24 | 0.16782 |
| 통과 없는 전송 처리 후 N/I 각각 | 24 | 0 | 24 | 0 |

기존 값은 N/A이므로 오류가 줄었다고 직접 비교할 수 없다. 보정하지 않고 기존 raw를 유지해
제공 가능해진 것이다. 전체 항목 4,392개에서 기존 보정 제공은 3,588개, 수정 후는 4,236개다.
raw 자체가 미측정인 156개는 그대로 미측정이다. 지원 증가를 실물 정확도 증가로 해석하지 않는다.

## 7. 코드·결과·한계

```powershell
python -m knowledge_estimation.simulation.compare_selective --output knowledge_estimation/data/selective_new_run
python -m unittest discover -s knowledge_estimation/tests -q
```

- `probabilistic/projection.py`: 원래 값 유지/보정 적용 공통 경로와 시각 기반 context.
- `probabilistic/selective.py`: 별도 검증에서 적용 여부 선택. 학습·검증 그룹 교차 검사.
- `simulation/compare_selective.py`: 계획 고정, 검증, 선택, 새 최종 평가와 악화 조건 보고.
- `data/selective_calibration_v2/RESULTS.md`, `summary.json`: 최신 결과.
- `final_by_case_phase.csv`, `final_by_condition.csv`: 표본 수와 전후/짝지은 Brier, 개선/악화 분류.
- `final_predictions.csv`: 원래/기존 보정/수정 후 값과 적용 또는 유지 이유.
- `selection.json`: 최종 평가 전에 고정한 게이트와 학습/검증 표본 수.
- `selected_model.json`과 `simulation_params.yaml`: 함께 사용할 최신 simulation 모델.

자동 검사 46개 통과. 실제 영상·내용 오류의 평가 데이터는 아직 없다. q=0.5/미측정 검사는 명시적
소프트웨어 fixture이며 물리적 정확도의 증거가 아니다. 미보고 reset과 미측정 raw도 남는다.
따라서 모든 조건의 정확도를 보장하거나 실물/규칙 시스템 준비가 완료됐다고 결론내리지 않는다.
