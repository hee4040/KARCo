# 통과 획득 확률과 데이터 품질 진단

현재 오류는 원본 추정기 구현만의 문제라고 볼 수 없다. **source와 평가의 조건 구성 차이,
방향·거리·가림을 생략한 확률 모델, 적은 고유 장면 수**가 함께 영향을 준다.
로그 손상이나 획득률 계산 오류는 이번 검사 범위에서 발견되지 않았다.
반면 시간 해상도에 민감한 검증 사례 1개는 확인했다.

추정기·확률·기존 정답 파일은 변경하지 않았다. 사후 보정도 적용하지 않았다.
최신 산출물은 `data/acquisition_audit_v3/`다. v1/v2는 감사 도구 개발 중의 예비 산출물이다.

## 무엇을 검사했는가

대상은 source `calibration_repair_v1/source_runs`와
`raw_revision_v1/{validation,test}/new/episodes`다.
validation/test 각각 288개 기록에 같은 통과 장면이 여러 개입으로 반복된다.
획득률은 개입 전 `normal_channel/after_pass`를 대표로 삼아 고유 기하 24개만 센다.
source는 고유 기하 72개다. 원본 대비 수정본은 이 시점의 확률이 동일하다.

| 검사 | 범위 | 결과 |
|---|---:|---|
| 파일 체크섬·수집 계약·쌍을 이룬 정답 | source 및 두 평가 분할 | 통과 |
| 별도 기하 계산: 시야·가림·연속 관측 시간·획득 시각·전달 결과 | 120개 고유 통과, 25,320프레임 | 불일치 0 |
| source 파라미터 재집계 | 확률/CDF 17개 전체 항목, 표본·시각·출처 포함 | 기존 파일과 일치 |
| 통과 후 DB 정답과 획득 trace 연결 | 평가 분할당 N/I 528개 | 불일치 0 |
| B DB·버전·TTL 등 정답 계약 | 분할당 항목 8,784개 | 계약 검사 통과 |
| A 관측만으로 추정 재실행 | 분할당 의사결정 1,464개 | 기존 추정과 일치 |
| 평가 CSV와 정답 연결 | 분할당 4,392개 | 불일치 0 |
| source/validation/test ID 및 정확히 같은 기하 겹침 | 분할 쌍 3개 | 겹침 0 |

별도 기하 계산은 생성기의 각도/사각형 slab 계산을 그대로 호출하지 않는다.
카메라 좌표계의 좌우/앞 거리와 선분-사각형 변 교차로 검사했다.
이 검사는 선언된 이상적 2D 모델과 로그가 일치함을 뜻한다. 실제 인식 정답 검증을 대신하지 않는다.
통과 뒤 각 개입의 전체 물리 상태를 외부 독립 시뮬레이터로 검증했다는 뜻도 아니다.

## 획득률이 왜 어긋나는가

현재 `p_acq`는 N/I·경로·장소·계획 속도별 빈도다. 실제 방향·가림·경로와 물체의 거리는
추정 입력에서 묶여 있다. 따라서 같은 속도이면 상당히 다른 장면에도 같은 값을 출력한다.
그 장면들의 구성 비율이 바뀌면 평균 획득률도 달라진다.

| 데이터 | 고유 기하 | 카메라 방향 | 경로 y좌표 |
|---|---:|---|---|
| source | 72 | 0/90/180도 | 0/0.5/1/1.5m |
| validation | 24 | 42/132도 | 0.32/1.32m |
| test | 24 | 48/138도 | 0.38/1.38m |

모든 분할에서 세 속도와 벽 유무는 균등하다. 그러나 방향과 거리의 구성은 같지 않다.
정확히 같은 기하의 재사용을 피한 것만으로 같은 분포의 독립 표본이 되지는 않는다.
이 평가는 새 기하 조건을 시험하는 설계 실험으로 해석해야 한다.

최종 평가의 속도별 통과 직후 결과:

| 항목 | 속도 m/s | source 획득/전체 → 추정값 | test 획득/전체 → 보유율 | Brier |
|---|---:|---|---|---:|
| N | 0.5 | 19/24 → 79.2% | 8/8 → 100% | 0.04340 |
| N | 1.0 | 19/24 → 79.2% | 7/8 → 87.5% | 0.11632 |
| N | 2.0 | 17/24 → 70.8% | 7/8 → 87.5% | 0.13715 |
| I | 0.5 | 19/24 → 79.2% | 7/8 → 87.5% | 0.11632 |
| I | 1.0 | 17/24 → 70.8% | 7/8 → 87.5% | 0.13715 |
| I | 2.0 | 12/24 → 50.0% | 6/8 → 75.0% | 0.25000 |

전체에서는 N 평균 추정76.4%에 비해 실제91.7%(22/24), I 66.7%에 비해83.3%(20/24)다.
source 자체에서는 집계에 사용한 빈도라 일치하지만, 독립 데이터에서도 맞는다는 증거는 아니다.
이 집계만으로 방향과 거리 각각의 기여를 완전히 분리했다고 볼 수도 없다.

방향·거리·벽별 최종 평가:

| 조건 | 항목별 장면 수 | N 보유율 | N Brier | I 보유율 | I Brier |
|---|---:|---:|---:|---:|---:|
| 48도 | 12 | 100% | 0.05729 | 100% | 0.12616 |
| 138도 | 12 | 83.3% | 0.14063 | 66.7% | 0.20949 |
| 벽 없음 | 12 | 100% | 0.05729 | 100% | 0.12616 |
| 벽 있음 | 12 | 83.3% | 0.14063 | 66.7% | 0.20949 |
| 경로의 최근접 거리0.62m | 12 | 100% | 0.05729 | 91.7% | 0.12616 |
| 경로의 최근접 거리1.62m | 12 | 83.3% | 0.14063 | 75.0% | 0.20949 |

벽 있음은 모든 프레임에서 가려졌다는 뜻이 아니라 벽을 설치한 조건이다.
거리는 경로와 물체의 최근접 거리이며, 인식한 순간의 깊이가 아니다.
평균 예측과 평균 보유율이 같아도 개별 장면을 구별하지 못하면 Brier는 남는다.
예를 들어 벽 있음 I는 평균 예측/보유율이 모두66.7%지만 Brier는0.20949다.

## 데이터 측면에서 주의할 네 가지

1. **겉보기 건수와 독립성**: 288기록을288개의 서로 다른 획득 장면으로 세면 과대평가다.
   고유24장면을 조건별로 나누면 속도별8장면, 완전한 조합별로는1장면뿐이다.
   같은 결정적 장면을 여러 번 재생해도 획득률의 근거가 늘지는 않는다.
2. **ID와 실체의 차이**: `object_instance` 등은 에피소드별 합성ID지만 물리 평가ID는
   모두`physical-Q`, 좌표계는`map`이며 환경·벽·물체 모델도 공유한다.
   ID 분할 검사 통과를 다른 물체·환경으로의 일반화로 해석할 수 없다.
   고정 환경 조건 시험에는 사용할 수 있지만 실체 단위 그룹 분할 검증은 미실시다.
3. **실측되지 않은 정답 생성 가정**: 정확한 물체 식별과 N=0.3초/I=0.6초의
   연속 가시성으로 반드시 저장하는 실험 모델이다. 이 시간을 실측 D455 식별 임계값으로 볼 수 없다.
   노이즈·오인식·픽셀 수·노출·실제 저장 처리는 검증하지 않았다.
4. **시간 해상도 경계 사례**: validation-009(속도0.5m/s, y=0.32m, 132도, 벽 있음)는
   원래1/30초 간격에서 최대 연속 가시 시간0.26667초로 N미획득이었다.
   간격을1/60,1/120초로 바꿔 같은 경로를 재계산하면 N획득이 된다.
   같은1장면의 변화이며 독립된 문제2건이 아니다. source와test의 N/I 획득 라벨 변화는0건이다.
   30Hz 관측 모델에 대해서는 원래 로그가 일관되므로 오라벨이라고 단정해 바꾸지 않는다.
   실기의 획득 주기·프레임 위상이 미확정인 경계 사례로 취급한다.

현재 데이터는 무작위 추출한 반복 시험이 아니므로 모집단 신뢰구간이나
필요 건수가 일률적으로 몇 개라는 주장은 하지 않는다.

## 다음 변경에 필요한 것

현재 추정값을 일괄 올리거나 이번test 빈도에 맞춰 바꾸지 않는다.

- **평가 목적 분리**: 같은 운용 조건 구성에서 확률을 검증하는 평가와 미경험 방향·거리·환경에
  대한 평가를 별도로 설계한다. 운용 구성비를 모르면 설계 격자상의 결과라고 명시한다.
- **A가 실제로 얻는 입력 확정**: 계획 경로·거리·방향이 A에게 전달된다면 계획값과
  B실행값을 구분해 기록한다. 계획과의 차이는 평가 전용이며 B의 실제 가시 상태를 A에 섞지 않는다.
  현재 실제 방향과 벽 조건은 평가 전용trace에만 있어 이를 사후 입력하면 부정확한 비교가 된다.
- **늘릴 대상 재검토**: 같은 장면 반복보다 방향·거리·속도·벽 배치·물체/지도가 다른 새 장면을 늘린다.
  확률 변동을 위한 반복은 측정된 노이즈 등이 들어간 뒤 별도로 센다.
- **획득 주기와 저장 조건 근거**: 경계 사례의 최대 연속 가시 시간과 임계값 차이를 남기고
  실측 획득 주기·저장 성공 로그로 이후 검증한다. 지금 기록과 확률을 손으로 바꾸지 않는다.
- **새 최종 평가**: 이번test를 원인 분석에 사용했으므로 이후 모델 선택 뒤에는 새 조건에서 평가한다.

수집 설계와 관측 계약을 먼저 정리한 뒤 조건부raw 모델 변경을 판단한다.
이번에는 추정기 변경을 늘리지 않고 데이터 구성·관측 부족 문제를 기록했다.

## 재현과 파일

```powershell
python -m knowledge_estimation.simulation.audit_acquisition --output knowledge_estimation/data/acquisition_audit_new
python -m unittest knowledge_estimation.tests.test_acquisition_audit
```

`summary.json`은 검사 결과, `conditions.csv`는 분할·속도·거리·방향·벽별 건수/확률/보유율/Brier,
`acquisition_designs.csv`는 중복 제거한 장면별 기록, `temporal_resolution.csv`는 시간 간격 감도,
`parameter_recount.csv`는 재집계, `split_overlap.csv`는 분할 중복 검사다.
입력manifest의 SHA256도 저장했다. 원본 데이터는 변경하지 않았다.
