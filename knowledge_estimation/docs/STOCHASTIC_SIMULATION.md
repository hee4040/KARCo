# 확률적 2D 세계와 장면별 참 획득 확률 p*

기존 `world.py`/`collect_designed.py`는 위치·방향·센서 위상이 정해지면 획득이 완전히 결정되는
결정론적 세계였다. 그래서 다음 두 문제가 있었다.

- 상대의 시점을 계산하는 추정기를 만들면, 시뮬레이터와 같은 코드를 쓰는 순간 오차 0이 되어 아무것도 검증하지 못한다.
- 0/1 정답과의 Brier만 계산할 수 있어서, 줄일 수 없는 오차와 추정기 오차를 나눌 수 없다.

새 세계는 무작위성을 **물리량에만** 넣는다. 획득 성공률을 직접 뽑지 않는다는 기존 원칙은 그대로다.
획득은 여전히 "기하 가시성 → 프레임별 검출 → 추적·연속 관측 시간 게이트"로 계산된다.
기존 코드와 v3 데이터는 재현용으로 수정하지 않았다.

## 1. 무작위성을 넣은 곳

| 층 | 모델 | 의미 |
|---|---|---|
| B 실행 | 계획 경로 주변 측면 오차·카메라 yaw 흔들림(정상 Ornstein–Uhlenbeck), 통과별 속도 배율 | 경로 추종 오차, 차체 흔들림 |
| 프레임 검출 | P_det = p_max × 크기항 × 시야 경계항 × 블러항, 로짓에 느리게 변하는 OU 교란 | 거리가 멀면 물체 픽셀이 작아짐, FOV 가장자리, 이동·회전에 따른 모션 블러, 조명 같은 시간 상관 요인 |
| 프레임 전달 | 프레임 누락 확률 | 드롭된 프레임은 미검출로 처리 |
| 저장 게이트 | 추적은 `track_max_miss_seconds` 이하의 공백을 허용, 추적 지속 시간 ≥ N 0.3초 / I 0.6초 | 한 프레임 놓쳤다고 바로 리셋되지 않는 일반적인 추적기 |

- 크기항은 `f·W/z` 픽셀 크기의 로지스틱이다. f는 시나리오 FOV와 1280px 폭에서 유도했다.
- 블러항은 카메라 좌표계에서 물체 방위각 변화율 × 노출 시간 × f이다. 따라서 속도와 근접 통과의 효과가 물리적으로 생긴다.
- 시야각·거리·벽 가림은 기존 `world.visible`을 그대로 쓴다. 기하적으로 보이지 않으면 노이즈가 있어도 검출되지 않는다.

모든 계수는 `simulation/noise_profiles.json`의 **선언된 실험 수준**(none/low/medium/high)이다.
측정값이 아니며, 실기 로그가 생기면 교체한다.

## 2. 지켜야 하는 계약

- `none` 프로파일은 `collect_designed.sample_pass`와 프레임 시각·자세·가시성·저장까지 정확히 같다. 테스트와 수집 품질 검사 양쪽에서 확인한다.
- 한 장면 = 한 번의 물리 통과(rollout 0)이다. 정답 K와 train 빈도 학습에는 rollout 0만 쓴다.
- 평가 분할(validation/test/ood)은 같은 계획 장면을 노이즈만 바꿔 R회 더 실행한다. p* = rollout 1..R의 획득 비율이다. rollout 0을 빼서 p*와 K가 독립이 되게 했다.
- p*, 노이즈 상태, 실제 실행 자세는 정답 전용이다. A 입력 allowlist는 바뀌지 않았다.
- seed는 `sha256([stochastic_plan_id, trial_id, rollout])`로 정해진다. 같은 계획이면 결과가 같다.
- 품질 검사에서는 모든 정답 rollout을 다시 시뮬레이션하고, 분할별 앞 50개 장면의 p*를 재현한다.

## 3. 평가 지표

`metrics.csv`에 기존 지표와 함께 다음이 추가된다.

| 지표 | 뜻 |
|---|---|
| `auroc` | 획득한 장면과 못 한 장면을 추정값이 얼마나 구별하는지 |
| `aleatoric_floor` | 평균 p*(1−p*). 어떤 추정기도 넘을 수 없는 Brier 하한 |
| `brier_of_p_star` | p*를 예측값으로 썼을 때의 Brier. 하한의 표본 확인용 |
| `mse_to_p_star` | 추정값과 참 확률의 제곱 오차. 추정기 자체의 오차 |
| `uncertain_scene_fraction` | 0.05 < p* < 0.95인 장면 비율. 세계가 얼마나 확률적인지 |

## 4. 결과 (seed 2026102301, R=64, 기존 속도만 쓰는 추정기 L0)

각 프로파일 12,240장면이고, 평가 분할은 장면당 64회를 반복했다. 아래는 test 2,160장면 결과다.

| 프로파일 | 항목 | 실제 획득률 | L0 Brier | AUROC | 줄일 수 없는 하한 | 불확실 장면 비율 |
|---|---|---:|---:|---:|---:|---:|
| medium | N | 48.6% | 0.247 | 0.56 | 0.019 | 10.7% |
| medium | I | 41.9% | 0.239 | 0.58 | 0.019 | 11.1% |
| high | N | 39.9% | 0.232 | 0.60 | 0.061 | 35.8% |
| high | I | 28.6% | 0.194 | 0.64 | 0.073 | 39.6% |

해석:

- medium에서 L0의 Brier 0.247 중 세계 자체의 무작위성으로 설명되는 부분은 0.019뿐이다. **나머지 약 0.23은 추정기가 방향·거리·가림을 반영하지 못해서 생긴 오차**다. 시점 기반 추정기로 줄일 수 있는 여지가 그만큼 크다는 뜻이다.
- 속도 효과가 생겼다. medium N은 0.5 m/s 53.9%, 2 m/s 41.0%이고, high N은 각각 48.9%, 28.2%다. 결정론 세계에는 블러가 없어서 이 차이가 작았다.
- 방향 [−120°, −60°)처럼 기하적으로 불가능한 구간은 노이즈가 있어도 0%다. 노이즈가 결과를 직접 만들지 않는다는 확인이다.
- ood_distance에서 L0 평균 47.7% 대 실제 38.2%(medium)로 여전히 어긋난다. 빈도표 방식의 외삽 한계다.
- L0의 AUROC가 0.5보다 높은 이유는 속도별 값이 다르기 때문이다. 같은 속도 안에서는 0.5다.

## 5. 재현

```powershell
python -m knowledge_estimation.simulation.collect_stochastic --output knowledge_estimation/data/stochastic_new --profile medium --rollouts 64
python -m knowledge_estimation.simulation.collect_stochastic --output knowledge_estimation/data/stochastic_medium_v1 --validate-only
python -m unittest knowledge_estimation.tests.test_stochastic_world -v
```

결과 위치는 `data/stochastic_medium_v1/`, `data/stochastic_high_v1/`이다.
분할별 `metrics.csv`에는 속도·거리 구간·방향 구간·벽별 지표가 있다.

## 6. 카메라 진행 방향 고정 옵션

`--camera-mount forward`를 주면 카메라가 경로 진행 방향에 고정된다. 경로 진행 방향은 6구간, 물체 쪽(왼쪽/오른쪽)은 무작위다.
이 설계에서는 결정론 기준(`sample_pass`)이 없으므로 노이즈 0 동일성 검사는 자유 방향 설계에서만 한다.
대신 테스트에서 "진행 방향 0°, 물체 왼쪽" 장면이 자유 방향 설계의 "카메라 0°" 장면과 같은지 확인한다.
결과는 [PERSPECTIVE_ESTIMATOR.md §8](PERSPECTIVE_ESTIMATOR.md)에 있다.

## 7. 다음 단계에서 주의할 점

- 시점 기반 추정기는 **noise_profiles.json의 참값을 읽으면 안 된다.** A는 D455 명목 모델과 자기 쪽 가정만 써야 한다. 차이는 calibration 분할의 보정으로 흡수하고, 그 결과를 프로파일별로 보고한다.
- 이번 test는 추정기 개발 전에 만든 것이지만, 개발 중에 test를 반복해서 보면 개발 데이터가 된다. 개발은 validation에서 하고, 최종 보고는 새 seed로 한다.
- 아직 모델링하지 않은 것: 부분 가림, 유사 물체 혼동, B 자기 위치 추정 오차(C 내용 유효성), 기억 초기화, 통신 채널.
