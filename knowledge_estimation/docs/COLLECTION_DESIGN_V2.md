# 균형 잡힌 획득 데이터 수집 설계와 실행 결과

2D 합성 데이터의 수집 설계를 수정하고 수집·품질 검사를 완료했다.
현재 권장 실행기는 `simulation/collect_designed.py`이며 최신 완료 데이터는
`data/designed_acquisition_v3/`, 조건별 분석은 `data/designed_acquisition_analysis_v1/`다.
기존 `simulation/run.py`와 보정 실행기는 과거 실험 재현용으로 보존했다.
이 문서는 실제 로봇 인식 성능을 검증했다는 주장이 아니다.

## 1. 기존 문제와 해결 방법

| 기존 문제 | 적용한 변경 |
|---|---|
| source와 평가의 방향·거리 구성이 다름 | train/보정/validation/test가 같은 조건 구간과 같은 표본 배정 사용 |
| 같은 통과 장면을 여러 개입으로 반복해 건수가 커짐 | 한 장면에서 한 번의 획득 기회만 기록, 고유 기하 중복 금지 |
| 방향·거리별 표본 수 부족 | 정밀도 목표에서 조건별 최소 수와 분할별 총 수를 계산 |
| 에피소드ID만 달라 다른 물체처럼 보임 | 실제 공유 물체`physical-Q`와 장면 해시를 그대로 보존 |
| 매 장면 센서 시작 시점이 고정 | 센서의 첫 프레임 위상을[0,dt)에서 별도 추출 |
| 미경험 조건과 일반 확률 평가가 섞임 | 환경·거리·속도 외삽 시험을 각각 별도 분할로 분리 |
| source 빈도 학습도 calibration으로 표시됨 | `fit_sources(..., fit_split="train")`을 지원해 역할을 명확히 구분 |

## 2. 무엇을 어떻게 뽑는가

정답을 보기 전에 모든 분할·장면·seed·실행 코드를 고정한다.
성공 여부는 확률로 뽑지 않는다. 위치·방향·센서 시점만 추출하고,
보이는 시간과 저장 조건을 기하 계산해 N/I 획득을 결정한다.

기준 분포는 아래 조합에 같은 비중을 주는 **선언된 실험 분포**다.
실제 운용에서 각 조건이 이 비율로 발생한다는 뜻은 아니다.

- 속도:0.5/1/2m/s.
- 경로와 물체의 최근접 거리:[0.5,1),[1,1.5),[1.5,2)m.
- 카메라 방향:[-180,-120),[-120,-60),[-60,0),[0,60),[60,120),[120,180)도.
- 벽 설치 여부:없음/있음.

108개 조합마다20개의 서로 다른 장면을 배정한다. 구간 내 거리·방향과 센서 위상을
서로 독립적으로 추출한다. 분할별 별도 난수 흐름을 사용하고, 조건·정답에 따른 재추출은 없다.
같은 seed로 같은 배정을 재현할 수 있다. trial ID에는 숨은 방향·가림 조합을 넣지 않는다.

| 분할 | 역할 | 고유 장면 수 |
|---|---|---:|
| train | p_acq와 성공 시각 F_pass 빈도만 학습 | 2,160 |
| calibration | 향후 보정 필요성 검토용, 현재 미사용 | 2,160 |
| validation | 고정 raw 모델 확인, 현재 모델 선택 없음 | 2,160 |
| test | 파라미터와 validation 결과를 고정한 뒤 생성·평가 | 2,160 |
| ood_environment | 다른 벽 배치·등록 배치의 환경 시험 | 2,160 |
| ood_distance | 거리[2,2.5)m로 범위 밖 시험 | 720 |
| ood_speed | 미측정1.5m/s 문맥에서 추정 보류 확인 | 720 |
| 합계 | 반복 개입을 곱하지 않은 장면 수 | **12,240** |

같은 물체·지도 모델을 공유하는 기준 분할에서 물체 일반화를 주장하지 않는다.
환경 시험은 실제 환경 설정의 해시가 달라야 하며 물체 자체는 동일하다.
표준 수집기는 획득만 다루므로 통신·ACK·규칙/PPO 성능을 이 데이터로 주장하지 않는다.

## 3. 표본 수를 정한 근거

임의 성공률이나 pseudo-count는 넣지 않는다. ±10%p와 분할별 실패 확률5%는
측정값이 아니라 변경 가능한 **실험 정밀도 목표**다.

속도3개·거리3개·방향6개·벽2개 각각에 대해 N/I 평균을 보려 하므로 총28개 평균이다.
독립적인 유계 관측의 Hoeffding 부등식과 합집합 상계로 다음을 사용한다.

`n_min = ceil(log(2 × 28 / 0.05) / (2 × 0.10²)) = 352`

방향 한 구간이 가장 작은 집단이며18개 조합을 포함한다.
조합당20개를 뽑으면 방향별360개, 속도별720개, 거리별720개, 벽 조건별1,080개다.
모든 주요 단일 조건 집단이352개 이상이 된다.
이 정밀도는 **해당 고정 합성 분포에서의 실제 획득 평균**에만 적용한다.
개별 장면의 예측 오차, 조합당20개 표본, 실기 성능 또는 두 분할 차이의 상계가 아니다.
같은 환경이 고정된 조건에서 기하·위상의 독립 추출을 가정하며 PRNG를 사용해 재현한다.

원문 근거: [Hoeffding, 1963, Probability Inequalities for Sums of Bounded Random Variables](https://www.tandfonline.com/doi/abs/10.1080/01621459.1963.10500830).
같은 내용의 [원문 PDF](https://www.cs.rpi.edu/academics/courses/spring06/random/hoefding.pdf).
이 논문이 우리의 장면 구간이나 실험 임계시간을 정해 준 것은 아니다.

필요한 정밀도가 다르면`--epsilon`, `--alpha`를 바꾸면 배정량을 다시 계산한다.
검사기는 목표를 만족하지 않는 배정을 거부한다. 단지 장면 수를 늘렸다는 이유로
더 많은 물체·환경을 검증했다고 주장하지 않는다.

## 4. 입력과 정답의 경계

장면별 세 파일을 구분한다.

- `A_inputs.jsonl`:현재 통신 계약에서 A가 받는 계획 속도·경로/장소 식별자·승인된 항목·통과 확인.
- `B_labels.private.jsonl`:초기 B DB와 통과 후 B DB, 세계 상태, 실제 획득 시각과 N/I 정답.
- `frames.private.jsonl.gz`:센서 시각·실제 자세·가시 여부·연속 가시 시간·저장 trace.

방향·벽·실제 거리·센서 위상·stratum·B 정답은 추정기에 전달하지 않는다.
실제 방향을 나중에 A가 알고 있었다고 가정해서 입력에 추가하지 않는다.
현재 계획 방향·거리의 전달 여부는 계약에 없으므로 미관측으로 유지한다.
향후 실제 A 계획 메시지에 해당 필드가 추가되면 계획값과 실행값을 별도로 수집해야 한다.

승인된 정상 배치와 통과 전후 정상 상태는 이 실험에서 공개된 정적 조건이다.
실기에서는 해당 상태를 확인한 관측 근거가 있어야 하며 상수True로 채우면 안 된다.
통과마다 빈 B 메모리로 시작한다는 조건도 실험 프로토콜이다.

raw 예측은 A 입력만 읽어 파일에 저장한 뒤 정답을 연결한다.
추정값이 없는 문맥에는0이나 평균값을 채우지 않는다.
새 파라미터는 획득 p_acq/F_pass만 포함한다. 통신·내용 품질 확률을 임의로 추가하지 않는다.

## 5. 시간 해상도와 경계 사례 처리

기준 관측 간격은 기존 실험의1/30초를 유지하고 첫 프레임 시점은 매 장면 달리한다.
장면 중간에 센서 위상을 재설정하지 않는다.
획득 시각은 실제 센서 표본 중 연속 관측 조건을 처음 충족한 시각이다.

같은 경로를1/60·1/120초 간격에서도 재계산해 민감도를 보관한다.
세밀한 시간 격자에 원래 표본 시각이 포함되도록 정렬한다.
경계 사례도 모두 유지한다. 성공/실패가 바뀐 사례를 제거하거나 정답을 손으로 고치지 않는다.

최종test에서 이런 민감 사례는 N7개, I2개다. 기준 주기에 대한 로그 검사는 모두 통과했다.
이는 숫자 손상이 아니라 획득 주기를 바꾸면 결과가 달라질 수 있는 모델 민감도다.
실제 장비의 주기·타임스탬프·프레임 위상이 측정되면 그 프로토콜로 별도 평가해야 한다.

## 6. 실행과 품질 검사 결과

최종 실행seed는2026102301이다. v1은 초기 검사기 개발 중 미완료 기록,
v2는 속도별6개 평균만을 대상으로 한 예비 실행이다. v3가28개 조건 평균 기준의 완료본이다.

다음 검사를 통과했다.

- 총12,240개 고유 기하, 조건별 배정 수 일치, 분할 간 정확한 기하 중복 없음.
- 총2,505,600프레임을 별도 카메라 좌표·선분 교차 계산으로 검사.
- 누락/중복 프레임과 장면, 입력/정답/trace 일대일 연결 검사.
- 실제 B DB와 획득 시각·버전·유효성 정답 연결 검사.
- train의 기회별 획득 기록을 재구성하고 파라미터 재학습 결과가 같은지 검사.
- 보정 분할에서 예측/보정 학습이 실행되지 않았는지 검사.
- A 허용 필드 검사, 모든 평가 예측을 A 입력만으로 다시 계산.
- 미측정 속도에서 N/I 각각720개가모두None인지 확인.
- 배정·파라미터·코드 고정값과 checksum 검사, 실행 코드 사본 보관.
- 자동 테스트59개 통과. 조건별 분석 추가 뒤 수집 관련5개 테스트도 재통과.

입력 누락, 정답 변조, 숨은 입력 추가, 고정 계획 변경을 거부하는 테스트를 포함한다.
`quality_report.json`과`manifest.json`에 검사 결과와 파일 해시가 있다.
조건별 분석기 역시28개 집단의 정밀도 조건을 검사하며, calibration 정답 통계는 읽지 않는다.

## 7. 새 데이터에서 확인한 것과 남은 모델 문제

현재 raw 모델 구조는 바꾸지 않았다. 새train의 실제 횟수로 획득률만 계산했다.
정상 분포test 결과는 아래와 같다. 각 항목2,160개의 서로 다른 장면이다.

| 항목 | 평균 추정 | 실제 획득률 | Brier |
|---|---:|---:|---:|
| N | 50.83% | 50.74% | 0.24848 |
| I | 45.09% | 44.72% | 0.24429 |

이전의 평균 차이가 수집·평가 구성 차이의 영향을 받았다는 진단과 부합한다.
그러나 다른 분포로 실험을 바꿨으므로 이전 Brier와 직접 비교해 성능 향상을 주장할 수 없다.
**평균 일치가 개별 장면을 잘 구별한다는 뜻은 아니다.**
예를 들어test에서 N은[0,60)도에서360/360개,[-120,-60)도에서0/360개를 획득했는데
평균 추정은 두 집단 모두50.83%다. 방향을 받지 않는 현재 모델의 한계가 드러난다.
그 입력이 실제 A에게 제공되는지 확정한 뒤 원본 모델을 수정할 근거로 사용할 수 있다.

환경 밖·거리 밖 시험은 기준 분포 평가와 합치지 않았다.
거리 밖 N은 평균 추정50.83% 대 실제40.00%로 여전히 어긋난다.
미측정 속도는 보간 확률을 채우지 않고 보류했다.

## 8. 실기로 옮기기 전에 필요한 근거

수집 설계와2D 검사는 완료했지만 아래 항목은 실측되지 않았다.
모두`collection_plan.json/hardware_status`에 표시한다.

| 항목 | 현재 상태 | 실제 수집에서 기록할 것 |
|---|---|---|
| 카메라 투영 | D455 명목 수치 | 사용 스트림 프로파일·intrinsics·설치 자세 |
| 관측 주기 | 실험30Hz와 합성 위상 | 프레임별 장비 timestamp, 누락·지연, A/B 시간 동기 오차 |
| 저장 조건 | N0.3초/I0.6초 실험 가정 | 실제 DB 저장 event와 획득 기회 ID, 원시 영상 근거 |
| 식별·내용 유효성 | 완벽한 식별/정확 좌표 가정 | 외부 검증한 물체ID·정상 배치·내용 유효성·좌표계·버전 |
| 계획과 실행 | 속도만 A 입력, 실행 오차 없음 | 실제 A 계획 메시지와 B 실행 궤적을 분리한 로그 |
| 독립 실체 | 고정 물체/지도 모델 | 세션·실물·환경의 실제 ID와 그룹 단위 분할 |

실제 수집에서도 같은 배정·역할을 사용하되, 실체가 같은데 다른 물체ID를 생성하지 않는다.
영상·독립 정답·DB 저장 로그가 없으면 실제 K 정답을 가시 시간으로 대신 만들지 않는다.
현재 파일은origin=simulation이며 실측 파라미터로 승격하지 않는다.

## 9. 재현과 결과 위치

```powershell
# 새 설계로 수집, train만 학습, 보정 OFF, 고정 후 평가 및 품질 검사
python -m knowledge_estimation.simulation.collect_designed --output knowledge_estimation/data/designed_new --seed 2026102301

# 기존 결과의 checksum·정답·원본 코드·배정 검증
python -m knowledge_estimation.simulation.collect_designed --output knowledge_estimation/data/designed_acquisition_v3 --validate-only

# 모든 단일 조건과 조합별 분석. 기존 데이터는 수정하지 않음
python -m knowledge_estimation.simulation.analyze_designed knowledge_estimation/data/designed_acquisition_v3 --output knowledge_estimation/data/designed_analysis_new
```

최신 결과:

- `data/designed_acquisition_v3/collection_plan.json`:조건·정밀도·입력 경계.
- `allocation_frozen_before_labels.json`:정답 생성 이전 배정과 코드 해시.
- `raw_parameters.json`:train만으로 계산한 확률과 조건부 획득 시각.
- `freeze_before_evaluation.json`, `freeze_before_test.json`:고정 기록.
- `quality_report.json`, `summary.json`:완료 검사와raw 평가 결과.
- `implementation/`:실행한 패키지 코드 사본.
- `data/designed_acquisition_analysis_v1/all_conditions.csv`:각 조건/조합의 표본 수·보유율·예측·Brier·시간 민감도.

후속 모델 수정에 이번test를 참고하면 그 데이터는 개발 근거가 된다.
최종 성능 주장을 위해서는 모델과 설정을 고정하고 새seed/장면으로 별도 평가해야 한다.
