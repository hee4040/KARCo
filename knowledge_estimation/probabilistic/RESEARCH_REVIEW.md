# 확률 기반 지식 추정: 논문 대조와 구현 검토

검토일: 2026-10-22. 검토 범위는 상대 지식 추정이며 팀원의 통신 선택/PPO는 제외한다.
논문의 접근 근거, KARCo HTML의 요구사항, 우리가 유도한 계산식을 구분했다.

## 판단

현재 구현은 **관측 가능한 획득 근거를 추적하는 확률 기반 기준선**이다.
아래 논문들이 사용하는 상대 믿음 추정의 방향과 일치하지만, 그 논문의 전체
베이지안 필터·POMDP·Dirichlet 추론을 재현한 구현은 아니다.

- ACK 미수신, 조건부 획득 확률의 곱은 명시된 통신/획득 모델에서 수학적으로 맞는다.
- 서로 독립인 획득 경로의 결합은 해당 독립성 가정에서 맞는다. 임의의 posterior를
  합치는 일반 베이즈 갱신식으로 사용해서는 안 된다.
- 버전/epoch 무효화, 정상 확인, 결과 검증은 HTML의 운영 규약이다.
- 0.8/0.9/0.95는 HTML의 예시/보정 대상 값이다. 논문에서 검증된 KARCo 파라미터가 아니다.
- 시뮬레이션의 숨은 리셋·재이동을 A가 아직 모르면 오추정이 남는다. 현재는
  이 발생률을 포함한 망각/상태 변화 hazard 모델이 없으므로, 그 구간까지
  보정된 posterior라고 주장할 수 없다.

## 수식과 코드의 대응

### 1. 저장과 유효성을 분리

`R`: B가 해당 정보를 저장함. `U`: 저장된 정보가 올바르고 사용할 수 있음.
`K = R ∩ U`라 두면:

```text
P(K) = P(R) × P(U | R)
```

조건부 확률의 곱이므로 R과 U의 독립성은 필요 없다. `Evidence.p_valid`가
이 계산을 한다. ACK는 저장된 항목/버전을 확인하지만, 같은 crop의 정확성이
확률 0.95라면 ACK가 와도 유효 확률은 0.95다. N/C도 A의 내용이 정확하다는
가정 아래 1이며, `content_quality`로 내용 불확실성을 전달할 수 있다.

### 2. ACK가 없을 때

이 식은 특정 논문에서 옮긴 식이 아니라 다음 KARCo 모델에서 직접 유도했다.

- D: 이 전송 시도에서 데이터가 정상 검증·저장됨, 확률 d.
- A: deadline 안에 그에 대한 정직한 ACK가 도착함.
- a = P(A | D). D가 아니면 ACK는 발생하지 않는다.

```text
P(D ∩ no A) = d(1-a)
P(no A) = (1-d) + d(1-a) = 1-da
P(D | no A) = d(1-a)/(1-da)
d=a=0.9 → 0.473684210526...
```

구현: `probabilities.receipt_given_no_ack`, `KnowledgeEstimator.observe_ack_timeout`.
조건부 a를 사용하므로 ACK와 D가 무조건 독립이라고 가정하지 않는다.
ACK deadline은 충분히 길어야 하며, 별도의 저장 실패/거짓 ACK 모델은 없다.
`d=a=1`에서 timeout은 불가능한 관측이므로 오류를 낸다.
전송 전/ACK 대기 중에는 새 전달 근거를 아직 반영하지 않는 지연된 기준선이다.
따라서 전송부터 deadline까지의 매 순간을 추적하는 완전한 통신 지연 필터는 아니다.

재전송은 시도별 전달/ACK 결과가 독립이고 캐시가 유지된다는 가정에서
‘하나라도 전달됨’을 결합한다. 같은 crop의 품질은 공통 잠재 변수이므로
전달 기회만 합치고 품질은 한 번 곱한다. ACK가 나중에 오면 명시된 저장 항목을
확인한다. msg_id/attempt_id로 중복 callback의 중복 가산을 막는다.

### 3. 이동 중 획득

```text
P(K from pass) = P(pass) × P(see | pass) × P(valid store | see, pass)
```

`p_pass`, `p_visible`, `p_store`를 이 조건부 의미로 사용한다. 단순히 세 개의
무조건부 성공률을 곱하는 해석은 맞지 않는다. `p_store`에는 올바른 항목의
저장/사용 가능성까지 포함한다고 가정한다. N은 정상 배치 확인 조건도 필요하다.

구현: `acquisition_probability`, `record_pass_by`, `confirm_pass_by`.
**이번 검토에서 수정:** 시뮬레이터가 기존에 알려진 거리/FOV와 관계없이 .8을
사용했다. 이제 `estimate_visibility`를 실제로 연결해 A의 알려진 기하상 불가능하면
0, 가능하면 설정된 조건부 확률을 사용한다. A가 모르는 가림은 여전히 입력하지 않는다.
통과 당시의 예상 기하는 고정해 두며 나중의 물체 이동으로 소급 변경하지 않는다.
통과 전에 A가 이미 이상 상태를 봤다면 `normal_before=False`로 N을 차단한다.

통과 전후 정상 확인만으로 중간의 상태가 확실히 같았다고 증명할 수는 없다.
이는 그 사이 미관측 변경이 없다는 프로젝트 가정이며, 실제 센서/시간 모델로
보정할 대상이다.

### 4. 여러 획득 경로

획득 성공 사건 S1, S2가 독립이고 한 경로의 성공이 다른 경로를 망가뜨리지 않으면:

```text
P(S1 ∪ S2) = 1-(1-p1)(1-p2)
pass .72 + verified handling .9 → .972
crop .95 + verified handling .9 → .995
```

구현: `independent_union`, `estimate`. 새 관측의 likelihood로 posterior를
갱신하는 일반적인 베이즈 식이 아니라, 유효 획득 경로의 합집합 확률이다.
같은 내용/공통 인식기를 재사용한다면 독립 가정이 깨질 수 있다.

- 같은 항목·버전의 전송은 하나의 content 그룹으로 묶는다. 같은 crop의 ACK가
  두 번 왔다고 .95를 .9975로 만들지 않는다.
- `dependency_group`을 같게 주면 그룹 내 최댓값을 쓴다.
- `independent_sources=False`는 전체 최댓값을 사용한다.

일반적인 합집합의 범위는 `max(p_i) ≤ P(any) ≤ min(1, sum(p_i))`다. 따라서
최댓값은 각 p가 유효할 때의 하한 근사이며, 정확한 상관 모델이나 보정된 posterior가
아니다. 서로 다른 그룹도 실제로 독립이어야 그룹 간 noisy-OR가 정당하다.
N/I를 한 스냅샷에서 함께 얻으면 각각 .72여도 두 항목은 상관되므로
정책에서 주변 확률을 임의로 곱해서는 안 된다.

### 5. 운영 규약과 확인되지 않은 값

| 규칙/값 | 근거와 판정 |
|---|---|
| 버전·memory_epoch 변경 시 이전 근거 무효화 | HTML 프로토콜. 논문 고유 수식이 아니다. 알려진 변경만 처리한다. |
| missing/not_found → 항목 확률 0 | 신뢰할 수 있는 명시적 부정 피드백이라는 가정. 센서 오검출/거짓 보고가 있으면 별도 likelihood 필요. |
| RESULT 뒤 A 재검증까지 외형 학습 보류 | HTML 규약. 재검증도 같은 인식기로 틀릴 수 있어 완벽한 정답이라고 간주하지 않는다. |

## 검증 방법과 범위

`tests/test_probability_model.py`는 단순히 함수의 식을 다시 계산하는 대신
전달/ACK/공통 crop 품질의 숨은 결과를 열거하고, 관측과 일치하는 결과만 남겨
확률을 정규화한 값과 구현을 비교한다. 독립 획득 경로도 모든 성공/실패 조합을
열거해 확인한다. 출처 의존성, 기하 제약, 이전 import 연결도 검증한다.

기존 테스트는 HTML 분기, 버전/epoch, 부정 피드백, 숨은 상태 비노출, 데이터
분할/인과성을 확인한다. 테스트 통과는 수학/코드/계약의 일관성을 의미하며
실제 로봇의 인식 확률이나 확률 보정 성능의 입증은 아니다.

검토 전 `data/synthetic_v1`은 유지한다. 기하 제약 수정 전 데이터이므로 현재
기준선의 결과로 혼용하지 않는다. 수정 후에는 `data/synthetic_v2`를 별도로
생성하고 manifest에 생성기 버전과 관련 소스의 SHA-256을 기록한다.

## ToM2C와의 구분

[ToM2C §3.2–3.5](https://arxiv.org/html/2111.09189v2)는 상대의 관측 관계와
목표를 신경망으로 추정하고 실제 관측/목표로 지도학습한다. N/C/I의 현재 유효한
캐시를 위 수식으로 추정한 선행 구현이 아니며, 현재 확률 기준선의 수식을
ToM2C에서 가져왔다고 설명하면 안 된다. `learning/`은 그 비교를 위한 데이터
준비 단계이고, 학습 모델/가중치는 아직 없다.
