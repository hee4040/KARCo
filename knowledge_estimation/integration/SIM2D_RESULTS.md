# 상대 지식 추정기: 팀 2D 시뮬레이터 연동과 최종 평가

담당: 상대 지식 추정(노션 적응형 통신 설계 v0.3의 `belief/estimator`).
시뮬레이터, 규칙 기반, PPO는 팀원 코드(`sim/`, `rule_based_comm/`, `rule_ppo_compare/`, `rl/`)를 쓴다. 이 문서의 모든 수치는 팀 2D 시뮬레이터 안의 값이며 실측이 아니다.

**요약 (2026-10-25, v2)**
- 통과 근거를 시점 기반 모델로 바꿨다. A가 명령한 경로를 자기 지도와 카메라 모델로 다시 그려서 B가 봤을 확률을 계산한다.
- 같은 경로·속도에서는 이전 빈도표와 정확도·통신 결정이 같다(사전 등록 비열등 기준 통과).
- B 속도가 바뀌면 시점 기반이 더 정확하다. 빈도표는 옛 값을 그대로 낸다.
- 규칙 정책과 연결하면 Confirmed Cache보다 전송량이 5개 조건 모두에서 적고, 보상은 3개 조건에서 유의하게 높다.

## 1. 작동 방식

```text
팀원 sim/world.py ── A가 볼 수 있는 사건 ──▶ integration/sim2d.py (CoreKnowledge)
                                              │ 사건 → 본체 호출
                                              ▼
                                  probabilistic/estimator.py (KnowledgeEstimator)
                                  항목(N·I·C)별 근거 = (출처, P(저장), P(내용이 맞음))
                                  통과 근거의 P(저장) = probabilistic/perspective.py
                                  b_raw = 근거 중 가장 강한 것 (독립 가정 없이 max 하한)
                                              ▼
                                  probabilistic/projection.py
                                  b_cal = PAV 보정표(b_raw),  b_safe = min(b_cal, 정책 상한)
                                              ▼
                     결정 직전 기록(b_raw·b_cal·b_safe, 근거, 지문) → 규칙/PPO가 b_safe를 읽음
```

| 시뮬레이터 사건 | 본체 처리 | 노션 |
|---|---|---|
| TASK·재전송·TASK v2·응답·POSE_UPDATE 전송 | `record_send` (재전송은 같은 msg_id, 다른 시도 번호). 보낸 것만으로는 저장으로 보지 않음 | §6 |
| ACK | `observe_ack`. 저장 확인(R = 1), 내용 유효성은 측정 r_crop·r_current | §6 |
| ACK 마감까지 미수신 | `observe_ack_timeout`: d(1−a)/(1−da), 측정 p_recv·p_ack·마감 | §6, ①(b) |
| needs_info, 정보 요청 | `observe_missing(needs_info)`: 해당 항목 무효화 | §6 |
| not_found | 진단 기록만. 원인 불명이라 C를 지우지 않음 | ④(d) |
| B 복귀 보고 | `record_pass_by`: A의 경로 지도 기준. 이상이 알려진 작업대는 정상 통과로 보지 않음. P(저장)은 시점 기반 모델 | ③ |
| A가 그 작업대를 다시 봄 | `confirm_pass_by`: 정상이면 사용, 이상이면 폐기 | §8 |
| A의 재검증 성공 | `record_result` + `verify_task`. RESULT ok만으로는 쓰지 않음, 측정 q_learn(verified) | ①(a) |
| 오조작 발견 | 외형 무효화, 해당 작업 근거 철회 | ②(d) |
| 기억 epoch 변경 | `observe_status`: 전체 무효화 | ②(b) |
| 위치 재측정 | C의 새 버전 등록, 이전 C 근거 무효 | §5 |

지나가며 본 이상은 C의 근거로 쓰지 않는다(버전 있는 보고만 인정). 측정값이 없으면 None이고 0이나 기본값으로 채우지 않는다. 정책 경계에서만 "모르면 B가 없다고 보고 보낸다"는 보수 규칙으로 0을 넘기며 그 횟수를 센다. 최종 평가에서는 0회였다.

### 통과 근거: 시점 기반 모델

1. A는 자기가 명령한 경로를 안다(`sim/world.py`의 `a_plans()`: 목적지별 B의 계획 위치·방향, 0.2초 간격). B의 D455는 진행 방향 고정이다.
2. A의 지도(작업대 위치, 가림막은 모름)와 카메라 모델(87°, 0.40–1.20 m)로 작업대가 시야에 든 프레임 수 n을 센다.
3. P(N 저장) = 1 − (1 − p_frame)^n, P(I 맞음) = P(N 저장) × q_learn(pass).

p_frame과 q_learn(pass)는 경로와 무관한 센서 비율이다. 이전 빈도표 p_acq는 (항목, 작업대, 경로)마다 따로 센 24칸이었다. 빈도표는 비교용 변형 `core_table`로 같은 세계에서 함께 돌며, 결정에는 쓰지 않는다.

## 3. 최종 추정 평가 (seed 400000–400199, 조건 5개 × 규칙·Minimal, 결정 28,216번)

결정 직전 추정과 그 순간 B의 실제 보유를 비교했다. 두 변형은 같은 세계에서 같은 결정에 대해 계산했다(규칙은 시점 기반 값을 읽음). 95% 구간은 에피소드 단위 bootstrap이다. τ = 0.8은 미리 고정했다.

### Brier (낮을수록 좋음)

| 추정 | N | I | C |
|---|---:|---:|---:|
| b_raw | 0.098 | 0.246 | 0.395 |
| **b_cal = b_safe (시점 기반)** | **0.0751** [0.0722, 0.0781] | **0.1649** [0.1614, 0.1687] | **0.2329** [0.2306, 0.2351] |
| 빈도표 b_cal (비교) | 0.0752 [0.0724, 0.0779] | 0.1652 [0.1613, 0.1690] | 0.2329 |
| Confirmed Cache | 0.271 | 0.618 | 0.396 |
| Confirmed Cache + Result | 0.200 | 0.360 | 0.396 |
| 낙관적 추정 (ablation) | 0.077 | 0.163 | 0.343 |

**짝 비교 (시점 기반 − 빈도표, 같은 결정):** N −0.0002 [−0.0004, +0.0001], I −0.0002 [−0.0005, +0.0001], C 0. 사전 등록 채택 규칙(N·I 모두 95% 상한 ≤ +0.01)을 충족했으므로 시점 기반을 기본으로 둔다. 조건별로도 같다. 예를 들어 가림막 조건 N은 0.071 대 0.071이다.

### 높은 추정·미보유 (b ≥ 0.8 중 B가 실제로 없던 비율)

| 추정 | N | I | C |
|---|---:|---:|---:|
| **시점 기반 b_cal** | 2.9% (21,107건) | 10.4% (14,088건) | 1.9% (1,242건) |
| 빈도표 b_cal | 2.9% (21,107건) | 11.4% (15,356건) | 1.9% |
| Confirmed Cache | 1.5% | 1.3% (2,035건) | 4.6% |
| 낙관적 추정 | 6.7% | 15.1% | 5.1% |

### 신뢰도 (시점 기반 b_cal 구간별 실제 보유율)

| 항목 | 구간 | 결정 | 평균 추정 | 실제 [Wilson 95%] |
|---|---|---:|---:|---|
| N | 0.2–0.4 | 6,659 | 0.280 | 0.312 [0.301, 0.323] |
| N | 0.8–1.0 | 21,107 | 0.971 | 0.971 [0.969, 0.973] |
| I | 0.4–0.6 | 12,509 | 0.432 | 0.443 [0.434, 0.452] |
| I | 0.8–1.0 | 14,088 | 0.899 | 0.896 [0.891, 0.901] |
| C | 0.2–0.4 | 26,974 | 0.384 | 0.412 [0.406, 0.417] |
| C | 0.8–1.0 | 1,242 | 0.987 | 0.981 [0.972, 0.988] |

해석:
- 같은 경로·속도에서는 시점 기반과 빈도표가 같다. 빈도표는 이 경로들에서 직접 센 값이고, 시점 기반의 차이(가림막을 모름)는 b_cal이 흡수했다.
- 두 변형 모두 자체 기준선(Confirmed Cache)보다 2–4배 정확하다. 이 결론은 v1과 같다.
- I의 약 10% 높은 추정·미보유는 추정기로 줄일 수 없는 불확실성이 대부분이다. v1 진단에서 원인의 76%가 B의 외형 오학습, 11%가 A가 아직 모르는 기억 초기화였고, 둘 다 A가 관측할 수 없다.

## 4. 분포 밖: B 속도 변경 (사전 등록 보조 시험)

B 속도만 바꾸고, 파라미터·보정표·빈도표는 0.15 m/s에서 잰 것을 그대로 썼다. A는 바뀐 속도로 계획한다(자기가 명령하므로).

| 속도 | 전체 짝 차이 N | 전체 짝 차이 I | I 높은 추정·미보유 (시점 / 빈도표) |
|---|---|---|---|
| 0.30 m/s (seed 410000+) | +0.0005 [−0.0006, +0.0016] | **−0.0018** [−0.0032, −0.0006] | 9.8% / 13.5% |
| 0.075 m/s (seed 420000+) | **−0.0016** [−0.0022, −0.0011] | **−0.0025** [−0.0031, −0.0019] | 10.1% / 10.1% |

**탐색적 분석 (결과를 본 뒤 추가, 사전 등록 아님):** 근거가 통과뿐인 결정만 보면 차이가 커진다.

| 속도 | 항목 | 빈도표 | 시점 기반 |
|---|---|---:|---:|
| 0.30 m/s | I Brier | 0.201 | 0.192 |
| 0.30 m/s | I 높은 추정·미보유 | 23.7% | 12.8% |
| 0.075 m/s | N Brier | 0.063 | 0.043 |
| 0.075 m/s | I Brier | 0.121 | 0.104 |

해석: 빈도표는 속도가 바뀌어도 옛 값을 낸다. 빨라지면 과신하고 느려지면 과소 추정한다. 시점 기반은 프레임 수를 다시 계산한다. 전체 Brier에서 차이가 작은 이유는 통과가 여러 근거 중 하나이기 때문이다. 속도를 바꾼 조건의 규칙 비교(통신 성능)는 아직 하지 않았다.

- 유사품 조건에서는 Minimal Push+Pull의 보상이 더 높다(−25.9 대 −31.0, 짝 검정 안 함). Minimal은 요청이 에피소드당 약 4회, 전송량이 약 1.7–1.9배다. 규칙이 사진이 필요했던 결정에서 처음에는 사진을 생략하기 때문이다(생략 비율 1.00). 규칙 비용 모델(`calibrated.py`, 팀원 코드)이 I 불확실성을 사진 비용보다 작게 보는 것으로 보인다(v1과 같은 경향).
- 시점 기반과 빈도표는 같은 조건에서 통신 결정이 사실상 같다. 차이는 경로·속도·배치가 바뀔 때 생긴다(§4).
- **PPO 모델은 이전 추정값으로 학습했다.** 시점 기반 값으로 다시 학습한 뒤 비교해야 한다.

## 6. 사전 등록과 실행 중 수정 기록 (2026-10-25)

최종 실행 전에 다음을 정했다.

- 최종 추정 평가: 처음 쓰는 seed 400000–400199 × 조건 5개 × 정책 2개(규칙, Minimal), 두 변형을 같은 세계에서 동시에 돌려 같은 결정에서 비교.
- 주 지표: 같은 결정에서 Brier(b_cal) 차이(시점 기반 − 빈도표), N과 I, 에피소드 bootstrap 95% 구간.
- 채택 규칙: N·I 모두 차이의 95% 상한이 +0.01 이하이면 시점 기반을 기본으로 둔다. 아니면 빈도표를 기본으로 되돌린다.
- 보조: 규칙 비교 seed 500000–500199. 분포 밖 속도 0.30 m/s(410000+), 0.075 m/s(420000+).
- 예상: 분포 안에서는 비슷하다(빈도표는 이 경로들에서 직접 센 값). 가림막 조건에서 시점 기반은 과대 추정한다. 속도가 바뀌면 빈도표가 틀린다.

**첫 실행 중단과 수정 2건 (결과를 보기 전):**
1. 속도 시험이 "보정표가 다른 추정기 것"이라며 거부됐다. 시점 기반 모델의 지문에 경로 계획(프레임 수)을 넣었기 때문이다. 계획은 모델이 아니라 입력이므로 지문에서 뺐다(카메라·알려진 벽·조건만 남김).
2. 같은 데이터로 b_cal을 두 번 적합했는데 쌍 수가 달랐다. 연결부가 메시지를 `id(payload)`로 구분해서, 해제된 payload의 id가 새 메시지에 재사용되면 새 메시지가 옛 메시지로 처리됐다(40판에 4건). payload를 에피소드 동안 붙잡아 id가 겹치지 않게 고쳤다. v1 결과(§7)도 이 버그의 영향을 조금 받았다.

두 수정 후 b_cal을 다시 적합했다(두 번 적합해 model_id 동일 확인). 상한도 다시 골랐다(여전히 없음). 최종 실행은 그 뒤 처음부터 다시 했다. 주 지표·채택 규칙·seed는 바꾸지 않았다.

## 7. 이전 결과 (v1, 빈도표 p_acq가 기본이던 때)

seed 200000–200199 추정 평가: b_cal Brier N 0.075, I 0.166, C 0.231. seed 300000–300199 규칙 비교: Rule + 추정기가 Confirmed Cache보다 5개 조건 모두 보상이 1.3–6.8 높고(p < 0.05) KB가 5.0–24.2 적었다(p < 0.001). 이 수치는 위의 id 재사용 버그가 있던 코드의 것이다. 코드와 원문은 커밋 `608d56d`의 이 파일에 있다.
